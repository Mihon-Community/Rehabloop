All displayed measurement values and the camera illustration on this page are invented examples. Fixture events must be visibly marked as simulated.
What the UI receives
measurement

Sequence, time, projected angle, rep count, state, quality, model version, optional simulated flag.

quality_warning

Reason and plain-language guidance. Clear the displayed angle until a usable measurement arrives.

error / socket close

Show a recoverable message, pause, and stop camera tracks. Resume requests camera access and a fresh stream token.

  • 5–8 fps in frontend; backend default cap 8 fps
  • JPEG, max image width 640 px, quality 0.65
  • Short-lived stream token, not user JWT
  • No audio capture or browser landmark overlay
Pause and end
Pause closes the stream and camera. End completes the session, stops camera tracks, and opens canonical results.

Result screen mapping
A

Fetch canonical record
`GET /api/v1/sessions/{id}` returns session status, metrics, quality flags, and persistence metadata.

B

Be precise about storage
When `persisted=false`, say it is in memory and not saved for later.

C

Explain quality
Render returned flags. Do not fabricate missing measurements or interpolate gaps.

D

Separate explanation from data
If the API summary is later added, keep canonical numbers sourced from the session record.

Backend available, UI not wired: the API provides progress and controlled summary endpoints. Current result code calls only the session GET.
Never imply durable save
Storage mode can be memory or Supabase. A result visible in the current session may not be available after refresh when it is memory-backed.

06 · States, layout, and design tokens

Make the safe state visible when the data or camera are unavailable.

These patterns apply across implemented and future screens. The current app has only a subset; the rest are part of the implementation checklist.

Core screen states

Connecting

Say what is loading and keep controls predictable.

Streaming

Show connection state with text and color.

Measurement unavailable

Clear the stale angle and give plain framing guidance.

Not saved for later

Use when the API says `persisted=false`.

Error message pattern

“The camera stream stopped. Your camera is off. Resume to reconnect.” Give one clear next step; never display raw server stack traces.

Responsive behavior

Desktop: live preview beside metric cards. At 720px and below, stack preview and metrics in one column. Keep nav wrapping and maintain action visibility.

The current app has this live grid breakpoint; keyboard focus and assistive-technology behavior still need dedicated review.

Safety rules to preserve

  • Keep all media tracks stopped on pause, end, and route exit.
  • No raw video storage; don't send frames or keypoints to summary provider.
  • Only a usable measurement gets an angle.
  • Fixture-generated events need a visible SIMULATED label.
  • Use the API's canonical numbers; never trust generated numbers.
  • Clinician owns protocol and interpretation.
